# การใช้งานร้านเดียวและการตรวจระบบ

ระบบเปิดข้อมูลร้านเดิมให้ POS, QR โต๊ะ, KDS, สต็อก, รายงาน และงานพยากรณ์โดยอัตโนมัติ สิทธิ์ owner, manager, cashier และ kitchen ยังแยกตามหน้าที่

## การย้ายฐานข้อมูล

- สำรอง PostgreSQL ด้วย `npm run db:backup` และกู้คืนในฐานตรวจสอบด้วย `npm run db:verify-backup -- <backup.dump>` ก่อนอัปเกรดฐานที่มีข้อมูล
- รัน `npm run db:migrate` แล้วเปิด API และ worker ด้วยโค้ดเวอร์ชันเดียวกัน Migration 025 กำหนดให้ร้านเดิม (`LEGACY`) เป็นร้านที่เปิดใช้งาน ข้อมูลของสาขาที่เลิกใช้เก็บไว้ในฐานข้อมูลเพื่ออ้างอิง
- ราคาหรือสถานะเปิดขายที่เคยตั้งเฉพาะร้านเดิมจะถูกนำมาใช้ในเมนูหลัก ประวัติการขายและราคาบนใบเสร็จเดิมใช้ค่าที่บันทึกตอนขาย
- ผู้ใช้ร้านเดิมและ QR โต๊ะเดิมใช้ต่อได้ บัญชีที่เคยมีสิทธิ์เฉพาะสาขาที่ปิดจะเข้าข้อมูลร้านไม่ได้ QR โต๊ะจากสาขาที่ปิดจะเปิดเมนูไม่ได้
- Node API และ worker กำหนดขอบเขตร้านเอง PostgreSQL ยังใช้ข้อจำกัดและ RLS เดิมเพื่อแยกประวัติที่เก็บไว้ การเพิ่มสาขา โอนสต็อก เปลี่ยนราคาตามสาขา และรายงานรวมถูกถอดจากแอป
- เอกสาร [ระบบหลายสาขาเดิม](multi-branch.md) ใช้อ้างอิงประวัติการพัฒนา

## ตรวจซ้ำข้อ 1–6

| ข้อ | การตรวจ | หลักฐานที่ชุดทดสอบตรวจ |
|---|---|---|
| 1 | เส้นทางงานหลัก | รับสต็อก, POS, สั่งด้วย QR, ครัวทำ, ส่งมอบ, จ่ายหลังทาน, ใบเสร็จ และปิดวันขายผ่านเบราว์เซอร์ |
| 2 | กระทบยอด | ยอดชำระที่บันทึกในข้อมูลทดสอบตรงกับรายงานและสรุปปิดวัน ยอดสต็อกตรงกับยอดรวมการเคลื่อนไหวและยอดรายล็อต |
| 3 | กรณีผิดพลาดและส่งซ้ำ | สต็อกไม่พอ, กู้คืนหลังผลตอบกลับหาย, ปิดวันขณะมีออเดอร์ค้าง, บล็อกยอดขายหลังปิดวัน และสิทธิ์การคืนเงิน |
| 4 | สิทธิ์ร้าน | ทดสอบตามบทบาท รวมถึงคำขอระบุสาขาเก่าหรือทุกสาขาและ QR สาขาที่ปิด |
| 5 | หน้าจอ | ทดสอบเดสก์ท็อปและจอมือถือ 390 px ด้วย Playwright รวมถึงโฟกัสคีย์บอร์ด การล้นหน้าจอ และ axe |
| 6 | ทดสอบหลังแก้ | รัน typecheck, build, integration tests, browser workflow และ concurrency benchmark |

ใช้ `npm test` สำหรับชุดทดสอบ API และฐานทดสอบในเครื่อง เปิด FastAPI แล้วใช้ `npm run build` และ `npm run test:e2e` สำหรับเส้นทางผ่านเบราว์เซอร์ และ `npm run test:load` สำหรับทดสอบแย่งสต็อกและส่งคำขอซ้ำ ชุดทดสอบเบราว์เซอร์และโหลดสร้าง schema แยกจากร้าน

ผลตรวจ 5 พฤศจิกายน 2569 ผ่าน 117 automated tests และ 37 กลุ่มตรวจเบราว์เซอร์บน Edge รวมถึงการปิดวันและกระทบยอด แบบทดสอบโหลดที่มีคำขอพร้อมกันสูงสุด 10 คำขออ่านสำเร็จ 100 ครั้ง จากการแย่งสต็อก 30 ครั้งขายสำเร็จ 2 ครั้ง และการส่งคำขอเดิม 20 ครั้งสร้างออเดอร์เดียว ผลโหลดใช้วัดการทำงานบนเครื่องทดสอบ

การตรวจใช้ธุรกรรมทดสอบในเครื่อง การนับวัตถุดิบจริง การทดลองกับผู้ใช้จริง และการทดสอบเครื่องพิมพ์จริงยังรอทรัพยากร
